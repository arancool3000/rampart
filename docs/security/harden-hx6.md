# hx6: RamPart Secure Browser and Safari integration hardening (2026-11-07)

Scope: `Sources/RampartBrowser/**`, `Sources/RampartSafariExtension/**`, `Sources/RampartApp/Features/SafariSetup/**`, `Extensions/safari/**`.

## Threat model

**Assets:** what the address bar and RamPart prompts say (the user trusts them), the user's cookies and storage in Banking mode, downloaded files (they must stay quarantined and must not escape the vault early), the persistent web allowlist (shared with Safari), Safari's Develop settings, and the isolation of the browser's content scanner.

**Attackers:**
- A malicious site or ad chain (the main one).
- Local malware running as the user. It can automate Safari, plant symlinks, and pick a bundle ID or name for itself.
- A malicious Safari extension sitting next to ours.
- A tampered file on disk.

**Entry points:**
- WebKit navigation and UI delegates (navigations, popups, permission requests, JS dialogs, downloads and their redirects).
- Script-message handlers.
- The page-world clipboard shim.
- `do JavaScript` replies in JS-control mode.
- The Accessibility tree in Safari setup.
- Messages from the Safari extension to its native handler.

## Needs owner (outside hx6's files)

- **N1 (High), Extensions/chromium/content.js:97,114,115:** the in-page "Trust this site", "Continue" and "Dismiss" buttons live in the page DOM and have no `isTrusted` check. A page can call `document.querySelector('#rampart-trust').click()` and allowlist itself permanently. Fix: build the UI in a closed shadow root (`attachShadow({mode:'closed'})`) and start every handler with `if (!e.isTrusted) return;`.
- **N2 (Med), RampartWeb/SafariScriptGuard.swift `AXTreeMatcher.extensionCheckbox` / `SafariSetupPlanner.plan`:** substring match on the extension name. Fix: exact match against a set of names, return nil if there is more than one; mirror `SafariAXDriver.exactExtensionCheckbox`.
- **N3 (Med), Extensions/chromium/interstitial.js:3-7:** the page is web-accessible to `<all_urls>` and shows headline and reasons from query parameters. Any site can frame it with attacker text in RamPart's voice. Fix: ignore `h` and `r`, fetch the verdict from background with `{type:"urlVerdict", url}`, and refuse to render when `top !== self`.
- **N4 (Med), Extensions/chromium/shared/clipboard-main.js:9 / content.js:165-170:** page-world `postMessage` lets the page forge `{__rampart:"clipboardDecision", allow:true}`. Fix: content.js should answer through a `MessageChannel` port it hands to the main-world script once at document_start, and should not accept window messages.
- **N5 (Med), Extensions/chromium/background.js:106:** `onMessage` doesn't check `sender.id === runtime.id` or that the message comes from the content script's own tab, and `setSettings` accepts any patch. Fix: check the sender, and whitelist setting keys and types.
- **N6 (Med), RampartWeb/URLAnalyzer.swift:436 `FileWebAllowlist`:** `allow()` writes unvalidated hosts to a newline-separated file. `isAllowed` walks up to any suffix that has a dot, so `co.uk` or `github.io` entries trust everything under them. Fix: reject hosts with non-hostname characters in `allow()`, and stop the walk at `PublicSuffix.split(h)?.registrable`. PublicSuffix also lacks multi-tenant suffixes (github.io, pages.dev, vercel.app, …).
- **N7 (Low), RampartWeb/NativeMessaging.swift `.allowHost`:** apply the same hostname validation server-side, because rampart-nmh (the Chromium host) skips the Safari validator.

## Honest limits

- **L1:** JS-control mode runs RamPart's scanner inside the page's own JavaScript world. A hostile page can always see it, find its state by enumerating `window`, and change what it reports. Safari's URL is now authoritative and mismatches are flagged, but the content signals stay best-effort. SafariSetupView now says so.
- **L2:** the browser's clipboard shim also has to run in the page world, because that's the only place clipboard writes can be intercepted. Prototype locks and realm hardening close the known bypasses. A cross-origin child frame (its own process) gets the shim injected separately. A brand-new realm reached in a way no hook sees is still a gap. The isolated-world scanner, its message handlers and all findings logic can't be seen or influenced by page scripts. They are in a separate `WKContentWorld`, and message handlers are registered only in that world.
- **L3:** the foreign-sender guard sweeps processes every 5 s and watches TCC logs. A sender that runs and exits between sweeps, without a new TCC prompt, can be missed. That's why the mode is labelled lower-security.
- **L4:** a quarantined file is protected by Gatekeeper only when it is opened through LaunchServices. Removing the flag needs the same user privileges the user already has.

## Status update: extension needs-owner items (extension hardening pass, 2026-11-07)

- **N1: Fixed.** All RamPart UI (interstitial, banner, clipboard dialog) is in a closed shadow root on a host with a random tag name, in the top layer (popover) where available, with inline `!important` host styles.
  Every handler ignores `!e.isTrusted` and clicks in the first 500 ms. "Don't warn" (`allowHost`) and "Continue" (`continueSite`) go to the service worker, which accepts them only from our content script in the tab's top frame,
  only for that tab's own host (taken from `sender.url`), and only if RamPart itself recorded a warn/block for that host in that tab. Hosts must be strict hostnames and more than a public suffix.
  Continue is session-only, per tab, per host. Watchdog: if the page removes or hides the block overlay, the tab is moved to the extension's own interstitial page. Honest limit: the host element is in page DOM and can be removed;
  for warn-level banners, removal is only undone three times.
  Also fixed: the run-once guard was `data-rampart-ready` on `<html>`, so a page could pre-set it in its markup and switch the content script off. It is now an isolated-world global.
- **N3: Fixed.** interstitial.js reads only an opaque 128-bit token from the fragment. Host, headline and reasons come from the service worker, only for our page in the tab the token was issued to. The page refuses to render when framed.
  WAR is `interstitial.html` only, http(s) matches, `use_dynamic_url: true`. The manifest CSP sets `frame-ancestors 'none'`. (The tab is moved there with `tabs.update`, so the WAR entry could probably be dropped entirely.)
- **N4: Fixed.** `shared/clipboard-bridge.js` (isolated world, document_start) creates a MessageChannel and hands the port over in one handshake. That handshake is queued before any page script runs. The MAIN-world hook accepts only the first handshake (same window, same origin, 32-hex nonce, one port),
  hides it from page listeners, and validates the nonce on every port message. No window messages are accepted for decisions or writes. tamper.js's forgeable window-message listener is removed. Clipboard prototypes are patched and locked (no instance-level bypass), and a "pending" answer now stops the 8 s auto-allow.
  "Don't copy" now actually rejects the page's promise. Honest limit: same-origin iframe realms keep unpatched prototypes. Safari needs the manifest entry (needs-web.md).
- **N5: Fixed.** `onMessage` rejects any `sender.id !== runtime.id`. Content messages need `sender.tab` and frame 0, and use `sender.url`, never `msg.url`. Popup and interstitial messages need an extension-page sender URL.
  `setSettings` accepts only `enabled`/`interceptClipboard` booleans or a subset of the current `allowedHosts`; anything else rejects the whole patch. Stored settings are re-typed on read. `interceptClipboard` is now honoured (it was ignored).
  Also fixed: `const { localVerdict } = …` in background.js re-declared a global from heuristics.js, so `importScripts` threw and the worker could not start. popup.js no longer puts the native host's version string into innerHTML.
