# Hardening hx4: web protection (DNS filter, DoH, blocklists, pf, Wi-Fi guards, network scanner)

Date: 2026-11-07. Scope: `Sources/RampartNetwork/**`. Regression tests: `Sources/rampart-selftest/SelfTest+HX4.swift` (`SelfTest.hx4Checks`).
Suites.swift line for the lead: `("hx4", SelfTest.hx4Checks),`

## Threat model

Assets: the Mac's ability to resolve names at all, the integrity of DNS answers, the block/allow decision, the pf ruleset loaded as root, the user's Wi-Fi connection, and RamPart's voice in the UI.

Attackers and entry points:
- **Hostile network / on-path attacker**: spoofed UDP to the resolver, forged DNS or DoH replies, a captive-portal or web-filter MITM, ARP and DNS spoofing to trigger (or suppress) Wi-Fi disconnects, attacker-chosen SSIDs.
- **Hostile LAN device**: crafted SSDP `LOCATION` URLs and mDNS packets read by the network scanner.
- **Compromised or broken list mirror**: oversized, binary, truncated, HTML, redirecting or poisoned blocklists and IP feeds.
- **Local malware running as the user**: flooding 127.0.0.1:53, sending crafted DNS messages, trying to make the resolver an open resolver.
- **Tampered file on disk**: `dns-original.json` snapshot, list files, pf paths and names.

## Needs owner (outside RampartNetwork)

- **N1 (High), `Sources/rampartd/Core/Integrations.swift` `WebProtection`**: the DNS-restore guarantee needs this daemon wiring. At daemon launch, before anything else, add `let sw = DNSSwitcher(snapshotURL: runtime.root.appendingPathComponent("dns-original.json"), dryRun: false); if sw.needsRecovery(filterRunning: false) { _ = sw.restore() }`. Then run a 10 s timer while web protection is on: `if let s = server, (!s.isRunning || !s.upstreamHealthy), let sw = switcher { _ = sw.restore(); switcher = nil; logWarn("DNS restored: filter unhealthy") }`. Re-apply when `upstreamHealthy` comes back. Also restore on SIGTERM/SIGINT. Without this, a crash or blocked DoH still leaves the Mac without DNS until the next start.
- **N2 (Medium), same file**: `DNSFilterConfig(port:)` uses the default `listenAddress` (127.0.0.1). Keep it that way; `start()` now throws on anything else.
- **N3 (Medium), blocklist signatures**: the lists are third-party and change every hour, so their hashes cannot be pinned. Plan: (a) the hosts are pinned through `isSafeSource` plus same-host redirects; (b) next step, RamPart publishes a mirror of each list, signed with Ed25519 (CryptoKit `Curve25519.Signing`, public key compiled into the app), as `<id>.txt` + `<id>.txt.sig` plus a manifest with entry count and date; `BlocklistUpdater` verifies the signature before `validate`. The owner of the release pipeline has to add the signing step. Until then the size, format and shrink checks are the integrity guard, and they cannot detect a subtle poisoning (a mirror adding a few real domains to block, or dropping a few).

- **N4 (High), release owner: DoH static pins.** `DoHPinStore.staticPins` ships empty on purpose. This agent had no network access to fetch the real Cloudflare and Quad9 keys, and a made-up pin would take DNS down. From a trusted network, connect to `security.cloudflare-dns.com` and `dns.quad9.net` and record `DoHPinStore.keyHash` of each intermediate CA key (plus one backup CA per host). Ship them, and review them whenever a provider changes CA. Until then, TOFU protects against interception that starts after the first connection, but not against a network already intercepting on the very first run.
- **N5 (Medium), daemon/app wiring for pin alerts.** Set `server.doh.onPinFailure = { host, detail in <emit a .network Detection, severity high, "Encrypted DNS was intercepted"> }` in `Integrations.swift`, and set `DNSFilterConfig.pinStateURL = runtime.root.appendingPathComponent("doh-pins.json")`. Offer a "Trust new key" action that calls `pins.forget(host:)`, only after the user confirms.
- **N6 (Medium), feed signing pipeline**: as N3. Once a signed mirror exists, set `publicKey` on the default sources.

## Honest limits

- Binding to loopback plus checking the source stops remote clients. Any local process can still query the resolver; that is how DNS works.
- DoH answer integrity rests on TLS to the upstream. A TLS-intercepting web filter with a trusted root CA can still forge answers, but now only answers that match our question and its CNAME chain.
- Pinned bootstrap addresses must be updated if Cloudflare or Quad9 renumber. If they do, TLS fails and the next upstream is tried.
- Wi-Fi: without Location permission there is no BSSID, so an evil twin with the same SSID and security as a trusted network is treated as trusted (alert only). An attacker who controls the network can also fake the "captive portal" signal to hide a DNS hijack. RamPart cannot fully stop either within macOS's rules.
- Blocklist integrity is heuristic until N3 (signed mirror) ships.
- Trust-on-first-use pinning cannot detect interception that is already in place on the first run. Static pins (N4) close that gap. A legitimate change of CA by a provider will look like interception: RamPart alerts and stops using that upstream, it does not keep going silently.

## Tests

`SelfTest+HX4.swift`: parser fuzz plus crafted loops, forward pointers, overlong names, overruns and escaping; loopback-only bind; bootstrap answers; dropped responses; upstream health; DoH question, ID, bailiwick, content-type and size validation; mock-URLProtocol poisoned-then-honest upstream; cache key and size; pf injection and reserved-range overlap; tampered DNS snapshot and crash recovery; updater binary, shrink and unsafe-source checks; public suffixes; SSID display; disconnect rate limit with a fake disassociator; scanner SSRF cases. No real network, pfctl, networksetup or Wi-Fi changes.
